# Lanpixo for iPhone and iPad

Native SwiftUI iOS 17+ source. Bundle ID **com.netora.scanner**, version **0.1.0 (1)**. This follows the owner's fallback identifier choice on 19 November 2026; the Android Play package cannot be renamed in its existing listing.

## Implemented source

- Network, Speed, History and Settings tabs; Turkish/English; system/light/dark themes; Dynamic Type and iPad layouts use standard SwiftUI containers.
- Real bounded IPv4 /22–/30 TCP discovery, up to 12 concurrent hosts, two passes and a 120-second deadline. Only successful connections and explicit ECONNREFUSED responses count as evidence. Timeouts never create devices. No simulated results.
- Bonjour resolution of declared service types; subnet-filtered IPv4 addresses and advertised names. No raw SSDP/multicast entitlement or private ARP/MAC API. IPv6 and complete discovery of silent devices are not implemented.
- Local device notes and recognition, observation-scoped to prevent IP-based trust transfer. Fresh scans reset recognition; restored lists and changed Wi-Fi are marked stale.
- Up to 20 local scan summaries and speed results; CSV file export with formula-injection protection; local-record deletion preserves preferences.
- Optional bounded Clouvider Frankfurt HTTPS speed measurement, about 5.3 MB plus overhead, with no cellular/expensive-network fallback. Short single-connection estimate, not a maximum-capacity measurement.
- Cancellation on backgrounding/network changes. No login, ads, IAP, backend inventory uploads or tracking SDK in this initial iOS build. Android monetization is not yet ported; use separate iOS AdMob units and consent integration before enabling ads.

## Build

Open `Lanpixo.xcodeproj` on a Mac with current stable Xcode. Select the Lanpixo scheme and your Apple Development Team. The committed project is generated by `../scripts/build-ios-project.py`; regeneration needs Python and Pillow but normal Xcode builds do not.

```sh
cd ios
swift test
xcodebuild -project Lanpixo.xcodeproj -scheme Lanpixo -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=NO build
```

The GitHub Actions workflow `../.github/workflows/ios.yml` runs core tests and simulator/device compilation on hosted macOS. Its artifact is an **unsigned simulator app**, not an installable iPhone IPA or an App Store upload. A successful CI run does not validate local-network discovery on an iPhone.

## Signing and TestFlight

1. Register `com.netora.scanner` under the correct Apple Developer team; verify it is available to that team. No extra network entitlement is assumed. If the identifier belongs to another team, resolve this before signing or uploading.
2. Create the Lanpixo iOS app record in App Store Connect, SKU `lanpixo-ios`, using the same bundle ID. Do not reuse the Android package as an Apple credential.
3. Build/archive on macOS with Apple-managed signing, or configure a trusted CI signing environment. Store distribution certificate/profile/API keys in the provider's secret store, never this repository or chat. No signing credentials have been provisioned by this project.
4. Validate the archive and upload to App Store Connect. After processing, start internal TestFlight testing before App Review.
5. Use genuine iPhone/iPad screenshots; Android screenshots are not valid iOS evidence. Publish the separate iOS privacy policy and complete App Privacy, age rating, export-compliance and trader declarations against the actual signed build. No export-compliance exemption is asserted in the project.

## Physical-device acceptance

- On actual Wi-Fi, test Local Network allow/deny/re-enable. Compare results with the router DHCP/online list; document sleeping/isolated devices. The simulator cannot establish permission/device-discovery acceptance.
- Stop and restart scans; background the app; switch/disconnect Wi-Fi. Confirm no old operation mutates a new result and partial results are labelled.
- Verify /22, /24 and /30 host boundaries; reject /21 and /31. Refused TCP is evidence; timeout is not.
- Test rename/recognition, fresh scan, relaunch, same-IP different devices, and network changes. Do not infer verified identity from Bonjour or IP.
- Test 16-port detail, cancellation, CSV containing quotes/newlines/formula prefixes, record deletion, accessibility text size, VoiceOver, TR/EN and iPad rotation.
- Test speed endpoint failure/cancellation/oversized body, Wi-Fi loss and no cellular fallback. HTTPS timings include request/connection overhead and are not ICMP ping or packet-loss metrics.
